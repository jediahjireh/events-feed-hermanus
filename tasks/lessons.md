# Lessons

Patterns and lessons learned during development. Review at the start of each session.

- **[Temporal]**: When in doubt about temporal type, prefer `"point"` or `"range"` with lower confidence over `"recurring"` or `"seasonal"` with higher confidence. It's easier to upgrade a point event to recurring later than to fix a wrongly recurring event.
- **[Sparse Data]**: Hermanus event data is sparser than expected. Google Events returns 3-5 results vs 20+ for Cape Town. The manual submission form is essential for coverage, not a nice-to-have.
- **[Facebook Gap → Apify proxy]**: Most Hermanus event organisers post on Facebook, but the Graph API severely restricts event search since 2019. This was identified in the pen-and-paper notes as a known gap under "What we can't get + how we mitigate." While browsing the Apify actor store during build, discovered `apify/facebook-events-scraper` — it scrapes Facebook Events by search query or URL, bypassing the Graph API restriction entirely. This directly addresses the gap documented in the design phase: Apify actors act as a proxy layer for platforms that restrict their official APIs. The same pattern applies to Eventbrite (`parseforge/eventbrite-scraper`), Meetup (`filip_cicvarek/meetup-scraper`), and TripAdvisor (`maxcopell/tripadvisor`). Consolidating on Apify actors as the source layer gives one API key, one billing model, and consistent fetch patterns.
- **[Verify All Claims]**: Design-phase documents accumulated stale numbers that propagated across files: wrong model names (Haiku 4.5 → 5.5), wrong pricing ($0.80/M → $0.10/M), wrong population (35K → 91K), wrong free tier limits (100 → 250 searches/month), non-existent APIs (Quicket has no public API), EOL frameworks (Next.js 15 → 16), and stale library references (Cheerio not used). Every factual claim — population, pricing, API existence, version numbers, free tier limits — must be verified against current sources before finalising. One wrong number cascades into every file that references it.
- **[Quicket No API]**: Quicket (SA's primary ticketing platform) has no public developer API as of Nov 2026. The Apify SA Events Scraper (`apify.com/gtnetworks/sa-events-listings`) is the workaround. Never reference `developer.quicket.co.za` or `docs.quicket.com` — they don't exist.
- **[SerpAPI — REMOVED]**: SerpAPI was the original Google Events provider but was replaced with the Apify Google Events actor (`johnvc/google-events-api---access-google-events-data`). SerpAPI phone verification blocked sign-up entirely — couldn't get an API key. The Apify actor provides the same Google Events data without a separate API key. Historical note: SerpAPI's `gl` (country) parameter was silently ignored for the Google Events engine — the `location` parameter or query string was required for geographic targeting.
- **[Verify API params against docs, not intuition]**: API parameters that are silently ignored are worse than ones that error — you don't know they're doing nothing. Always read the specific engine/endpoint docs, not just the general API docs.
- **[Apify consolidation]**: Consolidating all event sources on Apify actors (Google Events, Facebook, Eventbrite, TripAdvisor, Quicket) instead of multiple API providers (SerpAPI, Serper, etc.) gives: one API key, one billing model, consistent fetch/poll patterns, and a shared utility (`src/lib/sources/apify.ts`). The Apify free tier ($5/month platform credits) covers development. At scale, pay-per-result pricing avoids the cliff-edge plan tiers of services like SerpAPI.
- **[Model IDs go stale]**: The Anthropic model ID `claude-haiku-4-5-20241022` was used in 3 files but had been retired (Feb 2026). Model IDs with date suffixes are pinned versions that eventually get deprecated. Prefer the alias (`claude-haiku-5-5`) over the dated ID unless you need reproducibility. Check model availability before shipping.
- **[Verify actor I/O schemas before coding]**: The Apify `gtnetworks~sa-events-listings` actor's input/output fields were guessed during initial implementation — `searchQuery`/`maxResults` (wrong) instead of `cities`/`maxItems`/`upcomingDays` (actual), and output fields like `venue`/`organiser`/`image`/`link`/`priceRange` instead of the actual `venueName`/`organiserName`/`imageUrl`/`url`/`minPriceZar`/`isFree`. The code compiled and looked plausible but would have silently sent the wrong input and misread every output field. Always fetch the actor's README or run a test scrape to verify the exact field names before writing adapter code.
- **[Apify actor ID separator]**: Apify's website and documentation display actor IDs as `username/actor-name`, but the REST API interprets `/` as a URL path separator, returning 404. The API requires `username~actor-name` (tilde separator) in URL paths. The quicket adapter (`gtnetworks~sa-events-listings`) used `~` from the start because its ID was copied from curl examples, but the 4 new adapters (google-events, facebook, eventbrite, tripadvisor) used `/` from the Apify website and all 404'd. Fix: normalize with `actorId.replace("/", "~")` in the shared `apify.ts` utility so both formats work.
- **[Haiku 5.5 returns thinking blocks]**: Claude Haiku 5.5 returns a `thinking` block before the `text` block in `response.content`. Code that assumes `response.content[0].type === "text"` silently gets an empty string — the JSON parse then fails with "Unexpected end of JSON input". Always use `response.content.find(b => b.type === "text")` instead of indexing `content[0]`. This broke all 3 extraction/review paths and was only caught during live testing, not by unit tests.
